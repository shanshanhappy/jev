## 2. H：层级门控

### 生成请求体

```powershell
python core\schemes.py --scheme H --samples S001,S002 `
  --cat-tau 0.15 --cat-k 12 --gate-fallback all `
  --outdir out\payloads_H
```

- `--cat-tau 0.15`：类别概率达到 0.15 就保留其子标签；
- `--cat-k 12`：无论是否达到阈值，都额外保留概率最高的 12 个类别；
- 最终类别集合是“达到阈值的类别”和“Top-K 类别”的并集；
- `--gate-fallback all`：类别请求失败时回退全量叶子，优先保召回；`none` 则跳过叶子请求。

### 调用和评测

```powershell
python core\jev_client.py --dir out\payloads_H --all --scheme H `
  --raw-dir out\raw_H --platform official --proxy http://127.0.0.1:7897

python core\jev_eval.py --scheme H --mode cascade `
  --raw-dir out\raw_H --payload-dir out\payloads_H --gold new
```

**必须在同一次 `jev_client.py` 执行中运行类别和叶子阶段。**目前客户端只用本次运行内存中的类别概率筛选，不会读取历史 raw 来续跑第二阶段。中断后请重新运行两个阶段。评测报告和结果 CSV 默认写入 `--raw-dir` 对应目录，不再统一堆到 `out\` 根目录；如需另放可传 `--outdir`。

## 3. RAG：真正的向量语义检索

### 配置向量接口

默认使用 OpenAI 兼容的 `/v1/embeddings` 协议，可用环境变量配置：

```powershell
$env:EMBEDDING_API_KEY = "你的向量接口key"
$env:EMBEDDING_BASE_URL = "https://api.openai.com"
$env:EMBEDDING_MODEL = "text-embedding-3-small"
```

如果使用其他兼容服务，替换 base URL 和模型名即可。Jev 的 key 与向量接口的 key 是两套配置，不默认复用。

### 生成、调用和评测

```powershell
python core\schemes.py --scheme RAG --samples S001,S002 `
  --top-k 50 --outdir out\payloads_RAG

python core\jev_client.py --dir out\payloads_RAG --all --scheme RAG `
  --raw-dir out\raw_RAG --platform official --proxy http://127.0.0.1:7897

python core\jev_eval.py --scheme RAG --mode similarity `
  --raw-dir out\raw_RAG --payload-dir out\payloads_RAG --gold new
```

- 标签文本只由“标签名＋常见表达”组成；2026-11-20 起不再使用暂不可靠的所属类别和细分类别；
- 帖子和标签都通过向量模型生成 embedding，不再使用关键词命中率；
- 默认缓存为 `out/rag_embedding_cache.json`，只保存模型名、原文哈希键和向量，不保存原文；
- 标签向量只需计算一次，后续样本复用缓存；换向量模型后缓存自动隔离；
- `--min-score` 可选，设置后在 Top-K 中再按最低余弦相似度过滤；
- embedding 调用可能产生独立费用，不包含在 Jev 的 input token 统计中。

## 4. Speculative：两轮投机复问

```powershell
python core\schemes.py --scheme Speculative --samples S001,S002 `
  --lo 0.2 --hi 0.8 --spec-fallback none `
  --outdir out\payloads_Speculative

python core\jev_client.py --dir out\payloads_Speculative --all --scheme Speculative `
  --raw-dir out\raw_Speculative --platform official --proxy http://127.0.0.1:7897

python core\jev_eval.py --scheme Speculative --mode speculative `
  --raw-dir out\raw_Speculative --payload-dir out\payloads_Speculative --gold new
```

- 第一轮：A1 全量 638 问；
- 第二轮：只对概率在 `[0.2, 0.8]` 内的标签使用 A2 复问，边界值包含在内；
- `spec-fallback none`：第一轮失败时不再发起第二轮，避免无依据地增加成本；`all` 则第二轮回退全量；
- 评测与 CSV：第二轮覆盖同 qid 的第一轮概率，非边界标签继续使用第一轮结果。

## 5. 运行批次和结果口径

- 新客户端每次运行生成一个 `run_id`，写入每条 raw 记录；
- 评测和 CSV 只取每个“样本＋方案＋阶段”的最新批次，避免上一轮已问标签在新筛选结果中残留；
- 动态筛选后 0 问会写 `skipped=true` 的本地记录，不发 API；该样本仍保留在评测范围内，不能因 0 候选而从分母消失；
- `dry-run` 展示的是第二阶段候选上限，因为没有真实第一阶段概率，不会假装已完成动态筛选；实际节省以 raw 中真实请求 token 为准。

## 8. HybridRAG：强正则直接打标＋RAG 语义召回＋Jev 复核

> 2026-11-20 按用户确认口径实现。与旧 `Hybrid` 原型不同，也不是“正则候选全部送 Jev”：只有标签名精确出现且附近无否定才本地直接打标。

### 8.1 逻辑与产物

```text
D = 标签名精确出现且附近无否定的标签 → 本地直接打标
R = 标签名精确出现但附近存在否定的标签 → Jev 复核
S = embedding 余弦相似度 Top-K          → Jev 复核

Jev送问 = (R ∪ S) - D
最终标签 = D ∪ {Jev送问中概率 ≥ tau 的标签}
```

- 只把标签名精确命中作为直接打标依据，`hits` 中的近义词不能直接打；
- 否定窗口默认使用词库 `near`（通常 15 字）；一个位置有否定、另一个位置无否定时可采用干净位置；
- 否定命中不硬删除，交 Jev 处理双重否定和否定对象；
- 直接标签不重复送 Jev，RAG 仍阅读完整帖子；
- `core/hybrid_rag.py` 负责强正则、向量排名和候选合并；
- `候选标签_HybridRAG.csv` 保留 direct/review、直接打标、送问、证据、相似度和排名；
- `embedding_usage_HybridRAG.json` 记录向量请求数、缓存命中、实际 usage token 和缺失 usage 批次；
- 客户端把直接标签写为 `regex_direct` 本地阶段，Jev 写为 `leaf`，下游自动合并；
- 直接标签在最终细分表标记 `local-strong-regex / 本地强正则 / 强正则直接命中`；
- 生成请求体时会调用 embedding API，可能收费；候选召回评测不再调用 embedding 或 Jev。

### 8.2 配置向量服务并生成小样本

```powershell
$env:EMBEDDING_API_KEY = "你的向量接口key"
$env:EMBEDDING_BASE_URL = "https://api.openai.com"
$env:EMBEDDING_MODEL = "text-embedding-3-small"

python core\schemes.py --scheme HybridRAG --samples S001 `
  --top-k 50 --candidate-scan-k 200 `
  --outdir out\payloads_HybridRAG_S001
```

`--top-k 50` 是 RAG 候选上限，不等于实际 Jev 问数：直接标签会扣除，否定复核可能补充。`--candidate-scan-k 200` 只扩大审计范围，用于离线扫描。

### 8.3 不跑 Jev，先检查强正则和候选召回

```powershell
python tools\evaluate_candidate_recall_v023.py `
  --candidates out\payloads_HybridRAG_S001\候选标签_HybridRAG.csv `
  --top-k 20,50,100,200
```

输出：

- `候选召回报告_v0.2.3.md`；
- `候选召回汇总_v0.2.3.csv`；
- `候选漏标明细_v0.2.3.csv`。

报告按帖子 ID 对齐 v0.2.3、同帖标签文本去重，包含：

1. 强正则直接标签数、直接准确率 P、直接召回率 R；
2. 正则、RAG、并集候选召回；
3. 平均每帖候选数和扣除直接标签后的实际 Jev 问数；
4. 两路都未覆盖的正确标签明细。

若生成时使用了 `--min-score`，候选评测也必须传相同的 `--min-score`。

### 8.4 正式 Jev 调用和评测

```powershell
python core\jev_client.py --dir out\payloads_HybridRAG_S001 --all --scheme HybridRAG `
  --raw-dir out\raw_HybridRAG_S001 --platform official --proxy http://127.0.0.1:7897 --dry-run

python core\jev_client.py --dir out\payloads_HybridRAG_S001 --all --scheme HybridRAG `
  --raw-dir out\raw_HybridRAG_S001 --platform official --proxy http://127.0.0.1:7897

python core\jev_eval.py --scheme HybridRAG --mode hybrid_rag `
  --raw-dir out\raw_HybridRAG_S001 --payload-dir out\payloads_HybridRAG_S001 `
  --gold new --tau 0.9 --tag HybridRAG_S001_tau_0_90
```

即使某帖 Jev 候选为 0，也要执行客户端：它会把强正则直接标签写入 raw，并保留空候选帖子的 skipped 记录。随后将 `jev_eval.py` 生成的细分表和汇总表传给 `tools/compare_labels_v023.py`，按现行 v0.2.3 帖子 ID 口径计算最终 P/R/F1。不同 Top-K、qstyle 和阈值实验必须使用独立 outdir/raw-dir/tag。
