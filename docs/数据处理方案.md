## 1. 目标与边界

### 1.1 目标

把 47 列的原始导出数据，整理成**打标可直接使用**的 19 列清理版，同时**保住两条可回溯链路**：

| 链路 | 用途 |
| --- | --- |
| `id` → 原帖链接 | 人工复核时能点回原帖 |
| `csv_row_no` → 原始文件行号 | 任何一条结果都能定位回 `data_export.csv` 的第 N 行 |

### 1.2 边界（本方案**不做**的事）

| 不做 | 原因 |
| --- | --- |
| 不过滤行 | 清理阶段丢行不可逆。`is_main_post` 列保留，过滤放到抽样/打标阶段 |
| 不做标签判定 | 打标是下游环节，本方案只负责"把文本整理干净" |
| 不动原始文件 | `data_export.csv` 永久只读存档 |
| 不做情感标注 | 本次任务只判"有没有提到某话题"，不做正/负面 |

### 1.3 输入 / 输出

| | 路径 | 说明 |
| --- | --- | --- |
| 输入 | `data\data_export_clean_v2.csv` | 当前是原始文件的**完整副本**（MD5 已校验一致） |
| 输出 | `data\data_export_clean_v3.csv` | 清理版，**不覆盖 v2**，v2 留作回滚点 |
| 原始 | `data\data_export.csv` | 108.8 MB / 10,486 行 / 47 列，只读 |

> 目录约定：**所有工具脚本统一放在 	ools\ 下**，文档放在 docs\ 下，产出放 out\ 下。

## 3. 处理原则（6 条）

| # | 原则 | 具体要求 |
| --- | --- | --- |
| R1 | **原始只读，输出新文件** | 只读 `data_export_clean_v2.csv`，写 `data_export_clean_v3.csv`；任何情况下不覆盖输入 |
| R2 | **行不丢** | 输入 10,486 行 → 输出必须 10,486 行；清理阶段不做任何过滤 |
| R3 | **ID 全程字符串** | `id`、`csv_row_no` 一律按 `str` 读（`dtype=str`），**禁止**转数值、禁止过 Excel |

## 4. 列处理方案

**总账：47 列 − 28 删除 − 4 合并 + 4 新增 = 19 列**

### 4.1 删除 28 列

| 分组 | 列 | 删除理由（实测） |
| --- | --- | --- |
| 互动数值（8） | `Titan_interaction_cnt` `reposts_cnt` `review_cnt` `like_cnt` `fav_cnt` `fans_cnt` `follow_cnt` `specie_cnt` | 平均长度 1 字符，基本全是 `0`；与文本标签无关 |
| 空列/重复（4） | `rt_mid`<br>`item_id`<br>`data_typeV2`<br>`barrage_cnt` | 填充率 **0%**<br>与 `id` 完全重复（唯一值同为 10,486）<br>恒为 `["微博"]`，等价 `site_name`<br>9.1% 有值且全 `"0"` |
| 用户画像/隐私（6） | `uid` `red_id` `user_region` `post_region` `gender` `birthyear` | 与文本标签无关；删除同时降低个人信息合规风险 |
| 资源 URL（2） | `head_url` `video_urls` | 头像/视频地址，打标用不上（均值 118 / 124 字符） |
| 冗余分类（4） | `vtype` `kol_type` `post_type` `msg_type` | `kol_tier` + `volume_type2` 已覆盖分层；`msg_type` 仅微博有值（40.6%），跨平台稀疏 |
| 体积炸弹（1） | **`market_seg_product_object`** | 平均 5,534 字符/行、最大 234,030；是数说结论，用作评估会造成"自己考自己" |
| 其他（3） | `desc` `update_time` `sentiment` | 简介/更新时间无用；`sentiment` 是数说的 0/1/2 编码，本任务不做情感 |

> 备注：`sentiment` 仅占 1 字符，保留无成本；但按"不做情感标签"的口径建议删除。若后续要做口碑分析，可从原始文件按 `id` 回捞。

### 5.1 拼接顺序与标记

```
【标题】{title}
【正文】{content}
【图片文字】{cover_ocr_content}
【视频花字】{video_highlight_content}

```

| 规则 | 说明 |
| --- | --- |
| 空值跳过 | 某字段为空则整段（含标记）不输出 |
| 分隔符 | 段与段之间用单个换行 `\n` |
| 保留标记 | 标记约 40 字符/帖，但能让模型区分"作者写的"与"OCR 识别的"，对判断「卡粉」「色号」这类看图才知道的标签有帮助 |
| 不做去重 | 同一句话同时出现在正文和 OCR 时**不删**（说明该信息重要） |

## 6. 去噪规则

### 6.1 执行顺序（顺序错了会误删）

| 步 | 规则 | 处理方式 | 示例 |
| --- | --- | --- | --- |
| 1 | 编码规范化 | 去 BOM、`CRLF`→`LF`、删零宽字符（`\u200b` `\ufeff` `\u2060`） | — |
| 2 | HTML 实体 | 解码后再删残留 | `&nbsp;` `&amp;` `&lt;` |
| 3 | **谐音符号还原** | 仅做已知映射，**必须排在 emoji 删除之前** | `137🉐` → `137得` |
| 4 | URL 删除 | `https?://\S+`、`t\.cn/\w+`、`dwz\.cn/\w+` | `http://t.cn/AXWXV1XH` → 删 |
| 5 | @提及删除 | `@[\w\-\u4e00-\u9fa5]{1,20}` | `@怀豪堂` → 删 |
| 6 | 话题符号 | **保留文字**，只去 `#` `＃` `【】` | `#熬夜#` → `熬夜` |
| 7 | 圈号/序号符号 | 删 `①-⑳` `⑴-⒇` `⒈-⒛` `Ⅰ-Ⅻ` `❶-❿` | `①PROYA` → `PROYA` |
| **7b** | **补充符号** | 删 `2100-214F`（℃ ™ №）、`2190-21FF`（→ ← ↑）、`2200-22FF`（± ≤ ≥ ≈）、`25A0-25FF`（● ○ ◆ ■ □ ▲）、`FE00-FE0F`（变体符）<br>**白名单保护 `× ÷ ° % ￥ ¥` 不删** | `●干皮亲妈●` → `干皮亲妈`<br>`30ml×2瓶` → **保持原样** |
| 8 | emoji / 表情 | 删 Unicode emoji 区段（含 ❤️ 👍 🔥 🥲） | — |
| 9 | 重复字符压缩 | 连续 3+ 相同字符 → 2 个；重复标点 → 1 个 | `！！！！` → `！`；`啊啊啊啊` → `啊啊` |
| 10 | 空白规范化 | 多空格 → 1；连续 3+ 换行 → 1 个换行；去首尾空白 | — |
| 11 | 占位文本 | 删系统/占位句 | `分享图片`、`内容自动屏蔽`、`该楼层已被删除` |

### 6.2 三条硬约束

| 约束 | 说明 |
| --- | --- |
| **不许删否定词** | `不` `没` `没有` `并非` `无` `未` `别` `毫无` —— 打标的否定规则完全依赖它们，删了「没有搓泥」会变成「搓泥」 |
| **不许删数字与单位** | `137`、`30ml`、`2%`、`SPF50+`、`377`、`1.5`、`EUK-134` |
| **不许把英文/成分名当噪声** | `PROYA`、`B5`、`A醇`、`VC`、`烟酰胺`、`虾青素`、`双抗` |

### 6.3 白名单（必须原样保留）

| 类别 | 词 | 依据 |
| --- | --- | --- |
| 社媒黑话 | `k氧` `k糖` `敏皮` | 语义等价「抗氧化/抗糖化/敏感肌」。**实测 `敏皮` 直接出现在 4 个标签的命中词里** |
| 成分/科技名 | `麦角硫因` `虾青素` `双抗` `早C晚A` `EUK-134` | 依次出现在 **1 / 3 / 1 / 2** 个标签的命中词里（实测） |
| 否定词 | `不` `没` `没有` `并非` `无` `未` | 否定判定依赖 |
| 数字/单位/色号 | `137` `30ml` `2%` `SPF50+` `象牙色` | 价格、规格、色号类标签依赖 |
| **业务符号** | `×` `÷` `°` `%` `％` `￥` `¥` `‰` | **不是图标**：`30ml×2瓶` 是规格、`￥199` 是价格。误删会把 `30ml×2瓶` 变成 `30ml2瓶` |

> 注：`k氧` / `k糖` / `EUK` 在标签体系的关键词里**没有**登记（实测 0 条），但它们是社媒里「抗氧化 / 抗糖化 / 麦角硫因」的高频黑话，模型能理解，**必须保留**——同时这提示标签体系的关键词表有可补空间。

### 6.4 预期效果

| 指标 | 预期 |
| --- | --- |
| 去除字符总量 | 约 **37 万 + 补充符号约 900**（参考上一轮同源处理：emoji 6.1 万、URL 8,629、圈号 3.6 万、@提及、冗余换行） |
| 去噪率 | 约 **2~3%**（全文约 1,290 万字符） |
| `full_text` 平均长度 | 预计 **800~1,500** 字符 |
| 业务词损失 | **0**（白名单全保留） |

## 11. 已知缺口与风险

| # | 缺口/风险 | 影响 | 处理 |
| --- | --- | --- | --- |
| G1 | **标签ID 缺失 337 个** | 标签体系有 645 个唯一三元组，只能从 100 条样例明细反推 **308 个 ID**，剩 337 个无 ID | 需业务提供带 ID 的源表；过渡期该列留空 |
| G2 | **标签名有 11 组重名** | 如 `抗氧化` T124(功效)/T490(上妆问题)、`祛痘` T122/T100 | 主键必须用 `类别+细分类别+标签名`，不能只用标签名 |
| G3 | **`色调/色号` 一标签 16 行** | 象牙色/瓷白/珍珠白…共用"色号"这个标签名 | 打标时需把命中关键词当作子维度，否则 16 个色号会被压成 1 个标签 |
| G4 | **事件重复 2.77 条/事件** | 抽样不分组会造成评估泄漏、准确率虚高 | 抽样/切分按 `fingerprint` 分组 |
| G5 | **长帖极端值 51,744 字符** | 超模型上下文，必须截断 | 送模型时截 2,000 字；`char_count_full` 用于统计截断影响面 |
| G6 | **`is_main_post` 未过滤** | 若含回帖，混入后会污染样本 | 打标前用该列过滤，本阶段只保留列 |
