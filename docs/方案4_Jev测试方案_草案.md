## 1. 当前可以先做什么

不需要等待最终测试口径，即可先完成：

1. 对抽样清单的 100 条调用 Jev API；
2. 保存原始概率和 token/延迟；
3. 生成 17/12 列预测结果；
4. 与现有 100 条参考答案做对照，输出分歧清单。

若现有 100 条已人审确认，可作为正式对照；若为 LLM 初稿，本阶段结果只能称为“模型间一致率”，不宣称达到最终准确率。

## 2. 测试方案待确认的问题

| 待确认项 | 可选口径/影响 |
| --- | --- |
| 金标准有效性 | 当前 100 条是否全部人工确认；正式打标集何时到位 |
| 95% 指标 | 标签级 micro-F1、标签命中率，还是帖子级全对率；三者不可混用 |
| 样本代表性 | 当前偏促销/种草，是否补充差评、避雷、长文和对抗样本 |
| 命中阈值 | 暂定 0.5；是否扫描 0.2~0.8，是否分维度设置 |
| 灰区处理 | 暂定 [0.3,0.7] 转人工；是否根据概率校准结果调整 |
| 主提问方式 | A1/A2 选择；A2 提升不足 2 个百分点时倾向 A1 降本 |
| 请求打包 | 整包 638 问与分维度/分块结果是否一致，需抽测 |
| 分组级联H | 候选召回率目标≥99%；多次请求合计 token 相比全量降低≥50%；比较门控阈值/Top-K/回退策略 |
| 性能口径 | 官方限流与实际并发的取值；失败重试是否计入成本 |
| 成本口径 | 仅 API 费，还是包含灰区人审成本 |
| API 版本 | 官方 1.14 与中转 1.13 的结果是否允许混算（建议不混） |

## 3. 待口径确认后的建议测试层级

### T0：API 可用性

断言响应结构、答案数量、概率范围、usage 和结果文件生成，不涉及准确率。

### T1：口径验证

用当前 100 条对照 A1/A2，查看模型间一致率、分维度分歧、证据可定位率、阈值和打包漂移。此阶段可反哺提示词和人工复核优先级。

### T2：正式准确率

金标准版本和指标口径确定后，固定提示词与阈值重新跑批，输出总体/分维度/分层结果及 95% 判定。

### T3：性能成本

使用正式响应中的 token 和延迟，测算日处理 20 万、200 万的吞吐、费用及人审成本。

### T4：稳健性

针对长文截断、否定句、谐音黑话、重名/色号、多品牌帖子及不同模型版本做补充测试。

## 4. 当前原则

- 不因测试口径未定而阻塞 API 打标；
- 不拿 LLM 初稿冒充人审金标准；
- 不在验收前频繁改变提示词、阈值和样本范围；
- 正式报告必须写明金标准版本、指标定义、API 来源和模型版本。
