# 标签体系整理说明

> 日期：2026-11-15　|　原则：**原始标签体系文件不修改，只生成派生整理版。**

## 1. 文件分工

| 文件 | 行数 | 用途 |
| --- | --- | --- |
| `data\标签体系 20261113 - 【电商+社媒】细分维度词库.csv` | 678 | **原始真本，只读不动** |
| `data\标签体系_Jev整理版.csv` | 645 | 人工阅读、评审和确认 Jev 问题范围的主文件 |
| `data\标签体系_原始行映射.csv` | 678 | 每条原始规则行到整理版标签/qid 的回溯映射 |
| `data\label_lexicon.json` | 678 个原始对象 | 管道结构化输入，由原始文件生成 |

整理版的 645 个概念包括：

- **638 个参与 Jev 提问的叶子标签**；
- **7 个 TTL/集合汇总节点**，保留展示但标记“不参与 Jev 提问”。

## 2. 整理版新增字段

| 字段 | 含义 |
| --- | --- |
| `标签问题ID` | 生成 Jev 请求时使用的 qid；TTL 行为空 |
| `标签层级` | 叶子标签 / 汇总节点 |
| `参与Jev提问` | 是 / 否 |
| `代表词库原始行号` | 重复组内最小原始行号，预测输出和回溯使用 |
| `全部词库原始行号` | 同三元组的全部原始行号，保留评测候选关系 |
| `重复原始行数` | 该概念由多少条原始规则行聚合而成 |

其余命中词、且词、差词、正/负向词表保留原列名；聚合组内取有序去重并集，`near rule` 取组内最大值。

## 3. 为什么这样整理

原始文件有 8 组、41 行“类别+细分类别+TOPIC ANGLE”重复。如果直接逐行提问，会把同一 TOPIC ANGLE 重复询问。例如：

```text
标签问题ID: q0532
TOPIC ANGLE: 色号
代表词库原始行号: 533
全部词库原始行号: 533、534、…、548
重复原始行数: 16
命中关键词: 象牙色、象牙白、瓷白色、珍珠白、…、粉肤色
```

整理后：

- Jev 只问一次“是否提到色号”；
- 词表仍包含全部具体色号，供提示和证据回搜；
- 预测只输出一条“色号”，不出现 16 条同名记录；
- 金标准中的多行列表仍按该组命中处理；
- 具体色号值留在原文证据中；若业务需要逐色号分析，再增加“子值/命中值”列。

**跨类别同名不合并**，因为语义可能不同，例如功效与上妆问题中的“抗氧化”。

## 4. 聚合不会丢原始规则

整理版的合并词表用于提问提示、阅读和证据回搜，不替代原始规则引擎。

每条原始行的“命中/且/差/正/负向/near”完整保留在：

```text
data\标签体系_原始行映射.csv
```

因此即使同组内不同行的“且/差”条件不同，也能逐行回查，不会被合并词表掩盖。

## 5. 与 Jev 管道的一致性

`core\jev_prompts.py` 和 `core\jev_eval.py` 使用同一个 `core\jev_rules.merge_label_rows()` 聚合函数：

- 请求中的 qid 与整理版一致；
- 问题数量与整理版“参与Jev提问=是”的行数一致（638）；
- 预测输出的代表行号与整理版一致；
- 原始行映射可继续追溯到原始词库。

## 6. 重新生成

```powershell
python tools\build_lexicon.py    # 原始词库更新后先跑
python tools\build_taxonomy.py  # 再生成整理版和原始行映射
```

脚本只读原始文件，并带数量断言：645 个概念、638 个 Jev 问题、678 条原始行、qid 无重复。
