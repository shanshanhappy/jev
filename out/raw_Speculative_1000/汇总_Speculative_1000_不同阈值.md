## 二、主要结论

### 1. 当前 F1 最优点为 tau=0.90

- P = **39.5%**
- R = **65.0%**
- F1 = **0.491**

在已测试的 8 个阈值中，0.90 的 F1 最高。

### 2. 阈值从 0.60 提高到 0.90 后

| 指标 | tau=0.60 | tau=0.90 | 变化 |
| --- | ---: | ---: | ---: |
| 准确率 P | 26.4% | 39.5% | **+13.1 个百分点** |
| 召回率 R | 80.8% | 65.0% | **−15.8 个百分点** |
| F1 | 0.398 | 0.491 | **+0.093** |
| FP | 23,788 | 10,505 | **减少 13,283** |
| FN | 2,026 | 3,703 | **增加 1,677** |

说明提高阈值能明显减少误标、提高精确率，但代价是漏掉更多正确标签。

### 3. tau=0.97 过于严格

- 精确率提升到 53.5%，为全部阈值中最高；
- 但召回率降到 41.7%；
- F1 回落到 0.469；
- 预测标签只剩 8,234 个，漏标增加到 6,162 个。

因此 0.97 不适合作为综合工作点。

### 4. 成本不随阈值变化

所有阈值基于同一批 Raw 重算，因此平均输入消耗固定为：

- **28,908 token/帖**
- 1000 条约 **28.91M token**
- 官方 Jev 费用约 **$1.21**，按 ¥7.2/$ 约 **¥8.74**

阈值只影响本地命中判定，不会再次产生 API 调用费用。

## 五、建议

1. **如果只看综合 F1**：优先使用 `tau=0.90`。
2. **如果业务更怕漏标**：可使用 `tau=0.60`，保留 80.8% 召回，但要接受 23,788 个误标。
3. **如果业务更怕误标**：可看 `tau=0.97`，但 41.7% 的召回通常难以接受。
4. 不建议继续单纯调全局阈值，下一步应优先处理：
   - 内容类型尤其是软广漏标；
   - 效果表现、皮肤问题等状态类标签的误标；
   - 标签定义重叠及人工答案口径；
   - 分维度阈值或标签分组策略。
5. 当前所有阈值均未达到 95% 的 P 或 R 目标，仍需继续优化模型判定口径，而不是只靠阈值。
